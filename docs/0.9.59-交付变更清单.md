## 3. 旧协议运行时调用：**归零**（已核实）

E07 之后，模型回复的分派只剩唯一一条路径（`<atlasEdit>` 行增量）。核实方式与结果：

- `src/atlas-server.ts` 中**不存在** `protocol === "v1"` / `protocol === "v2"` / `case "v1"` / `case "v2"` 任何分支；
- `applyAtlasV2Turn(` / `parseAtlasWorldTurnDraftV2(` / `parseAtlasWorldTurnDraft(` 在 `src/` 下**没有任何调用点**（只有定义与注释）；
- `runtime.update` 写入 `worldTurnProtocol` 时只接受 `table-delta-v1`，写 v1/v2 → 400 `INVALID_PAYLOAD`；读取侧把缺失/非法/v1/v2 一律规范成 `table-delta-v1`；
- 浏览器入口（`src/atlas-browser-entry.ts`）**不再导出** v2 解析器与旧提示词分段；
- 模型若仍回 v2 封套 → **409 `PROTOCOL_MISMATCH`**（`$.schemaVersion`、带迁移入口文案），明确**不当作 noop**。

### 3.1 但：旧模块文件仍在树里（未删除）

`src/atlas-turn-v2.ts`、`src/atlas-contract-v2.ts` 以及 `src/atlas-api-client.ts` 里的 v1/v2
草稿解析与提示词构造函数**仍然存在**，只是**从运行时不可达**。

**如实说明**：这是「运行时淘汰、代码保留」，不是「文件删除」。保留用于旧档读取与历史对照；
代价是仓库里留有一批不可达代码，后续可安全清理。

### 7.3 已发现、记录在案的问题（**均已在收尾轮修复**）

> 下面两条都是**验证阶段发现、随后修掉**的真问题：先按实测写下现象与根因，
> 修复后保留原文并标注「已修」与回归用例位置——不做无痕删除，便于审计对照。

4. **`ensureMapScaleOnCreate` 的 `!preset → API_NOT_CONFIGURED` 分支在 HTTP 路径上不可达。**
   `loadSettings()` 是按请求实例缓存的（`settingsLoaded` / `settings` 均为 createCoreInstance 局部），
   而三个调用点在同一请求里都已先解析过 preset 才走到标定。因此计划 T25「没 API 也建图」
   当前只能以两种方式成立：(a) 开场本身被具名拒绝（409 `API_NOT_CONFIGURED`）；
   (b) 标定请求失败 → `scale-pending` + 具名码。两者都已有测试覆盖。
5. ~~**行增量新建的内层地图在 `maps` sidecar 里没有 `submaps[key]`**~~ → **已修**。
   `handleScaleCalibrate` 过去只用 `doc.submaps[mapId]` 校验宿主与父图，而 `maps.submaps`
   只由 geo-apply（提炼/采纳）写入；行增量开场/回合建出的图不走那条路，
   于是对该子图调 `/worlds/scale/calibrate{userMetersPerCell}` 返回 400
   「子图标定的宿主点位或父图不存在」——界面看得到子图、标定接口却不认，
   **「待定 → 人工锁定」在教室这类图上直接不可用**。
   现在按**三表投影**再认一次宿主（该 `loc:<mapId>` 行存在且确有孩子挂靠即认定为真子图），
   同时**保留守卫**：没有任何子地点挂靠的 mapId 仍返回 400。
   回归用例：`tests/atlas-simulation-commit.test.mjs` 的
   「H23 修复：行增量建出的内层地图可以做人工标定（不再 400 宿主不存在）」。

6. ~~**「声明了关系但没有引文」被报成「本来就没有关系」**~~ → **已修**。
   实测根因：`judgeGeoRelation` 本来就返回 `verdict:"pending"` + `reasonCode:"NO_EVIDENCE"`，
   但 `planGeoRelations` 只接住了 `contained` / `adjacent` 两种 verdict，
   `pending` 分支**没被接住**，于是预览行落到默认的 `NO_RELATION`、`pending:false`——
   作者看不出「模型主张过这条关系、只是缺证据」。
   计划 H05 原文要求「没有引文或引文不在世界书/正文时把该关系**留待用户确认**」，
   现已按此接住 `pending` verdict（`reasonCode` 具体到 `NO_EVIDENCE` / `QUOTE_NOT_FOUND`）。
   回归用例：`tests/atlas-geo-extraction-chain.test.mjs` 的
   「H05：声明了 contained 却没有引文 → 进 pending（NO_EVIDENCE），不退化成「无关系」」。

### 7.4 有意为之的设计决定（非欠账）

## 8. 测试失败项

**无。** `npm test`：981 / 981 通过，0 失败，0 跳过。

会话期间修掉的两个真实缺陷（均已落地并有回归测试）：

- **D03 时间三来源只有两条接通**：`deriveElapsedPeriods` 是死代码，导致「助手正文写
  『睡到翌日 / 赶了半天路』」在行增量回合里完全不计时段。现已是唯一时间来源。
- **消息传播卡在第一跳**（D02/T06/T21）：调用点传的是**本轮增量**跳数，而传播函数每轮
  都从发起地按该跳数重算候选集，`cursor` 又被夹住 → 连续单时段回合下第 2 轮 0 条新送达，
  消息永远到不了第 2 跳。现改为**自发布起累计的跳数预算**（`hopBudget`）。
