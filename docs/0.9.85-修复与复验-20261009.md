# ATLAS 0.9.85 修复与复验

基线：`codex/world-construction-and-story-feed` / `ba8cffa`（0.9.84）。

## 修复

1. 导航层级与渲染几何分别传递。房间/建筑仍保留真实导航类型，已保存 floor 场景走室内画法、命中及小地图。
2. 首轮、初建和移动后的建设焦点从 observe 已应用的候选解析；建设请求携带完整字段合约及对象名称、类别、父关系。
3. 建设保留已确认父关系、精确坐标与范围；按实际回复限制每批 12 新地点、16 路线、2 条新增父边，并递延依赖对象。完整剩余目标不再截成 64 个，目录祖先不计入待建设范围。
4. 前景、修复、建设、后台、布局和 MiniMax 兼容发送共用局部传输预算。实际 fetch 前扣额，已到期后台可使用预留额度。
5. 单间房允许铺满自身幅面；阅览桌与整套桌椅的类型和尺寸要求明确。布局仍有失败细节时建设状态保留 partial。
6. 尚未绘制的世界根图加入自动布局候选，继续遵守每批最多两张图。
7. 重开从 SQL 恢复原生回执、问题及各阶段摘要；回退后不恢复已撤销回执。诊断数量以实际问题为准。
8. 真实酒馆门禁核验新回执身份、宿主保存 ACK 和原生状态，消息增加不再当作提交成功。
9. 同批新建物品再转移物品按引用处理，避免重复声明；编译时允许读取本批有效的新物品，合并变更保留最初的 null before，创建后转移仍按插入记账。初始落点和存在质量提示补齐枚举，测试要求无需额外纠错请求。
10. 区域多边形实际使用方向参数，保留锁定坐标；河道提示补齐起止方向。短宿主窗口内左侧导航可滚动，底部视角按钮不会溢出到事件栏背后。
11. 布局回复格式错误且没有有效变更时禁止假报 committed；有独立有效变更则 partial，现有世界保留。
12. 布局请求失败的原生回执、路径、行号与尝试摘要回传到推演回执。失败状态优先于零变更成功组，防止旧适配器再将 failed 改叫 committed。
13. 普通楼层传递当前用户人设名；尚无主角时，只为唯一精确同名档案补主角身份并记录用户来源。保留已绑定主角，重名不随机选择。来源提示要求完整 key，避免数字序号被当成来源名。
14. 单室载具和房间的容器本身属于自己的室内图；外层地图坐标不覆盖明确的室内归属。连续布局保留旧房间、家具和留场人物，真实离场人物仍移除。新增两次候选提交的回归测试，修复前可重现误剪，修复后通过。
15. 地图写入成功后允许本聊天修订号/快照变化，继续登记并刷新本轮回执；读操作仍核对完整快照。另一个聊天或分支的晚到结果不接收。此前完整快照守卫把正常保存后的回执也跳过，此问题在实际更新布局时发现并补回归。

## 范围

世界内容按预算分批建设；一次有限批次成功不能代表所有地区、房间和布局已生成。新生成且缺少已注册事实支持的空间仍标 inferred。在线结果有模型差异，partial 仍需查看问题并继续处理。

复验环境为 Windows / Chrome / 当前本地连接；未覆盖多提供商和长时间负载。没有推送或合并 main，也没有清理旧测试聊天。

本报告验收的是上述缺陷修复，不签署原施工包 M0→M7 / 119 项全通过。真实浏览器的楼层删除/变体全流程、模型等待时切聊天、连续十次切换，以及 NPC 未告知秘密的完整后台推进链尚未验收；相关自动回归通过不能替代在线门禁。当前酒馆使用内嵌 SQL 后端，独立 Server 插件未安装，所附 Server 包仅经过类型检查、自动测试和构建。
