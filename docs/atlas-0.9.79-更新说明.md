# Atlas 0.9.79

修复酒馆生成一楼后没有推演反应的接线缺口，保持用户提供的原版 UI 配色、CSS、字体与地图交互。

## 修复

- 回复超过 24,000 字符或用户消息超过 12,000 字符时，模型输入仍按原预算截取，提交有效性改为比较完整宿主正文。修复长楼层未调用模型、无回执、无错误的静默丢弃；请求期间改动超出预算的正文也会拒绝保存并给出诊断。
- 保留酒馆事件的完整参数，包括 `GENERATION_STARTED(type, params, dryRun)` 和 `MESSAGE_RECEIVED(messageId, type)`。排除首次开场消息、quiet、dryRun 和后台自动请求，避免误推演；后台 quiet 完成通知不会吞掉已有真实回合的正文完成通知。
- 同时监听 `GENERATION_ENDED` 与 `GENERATION_ENDED_AFTER_COMMANDS`，通过现有防抖与提交锁去重。任一完成通知路径都可结束真实回合。
- 未提交或失败的楼层重新生成／右滑时，即使没有新的 `MESSAGE_SENT`，也使用实际用户楼层重新准备回合。
- 已提交楼层重新生成时，先完成宿主删楼／换变体的世界回退，再准备替代回合；快速生成也等待回退结束。同一楼层可连续重新生成。
- 新 UI 同步实际回合阶段，显示等待正文、读取资料、排队与推演状态；保留成功／失败回执和本轮日志入口。

## 验证

- 类型检查、构建、打包和完整 1617 项测试通过。
- Chrome 使用实际安装包、真实 SQL 引擎和酒馆事件签名完成 25 项生成链路检查：普通楼层、真实地点与回执渲染、超长双方文本、完成事件去重与兼容、静默／自动门控及恢复、开场消息、嵌套 quiet、请求期间正文后缀变更、无 API 的失败回执，以及未提交与已提交楼层的连续重生成。
- 原版 UI 浏览器检查和 SQL 发布包检查通过；两份原版 CSS 与字体哈希一致。

上述测试使用隔离宿主和测试模型响应，没有调用用户在线模型。已确认旧版本存在长楼层静默丢弃和无新用户消息的重生成漏接，但用户这一楼的具体原因仍需真实酒馆诊断记录确认。

## 更新

在酒馆扩展管理中更新 Atlas，然后刷新页面；手动安装使用 `atlas-ui-extension-0.9.79.zip`。安装后核对版本为 0.9.79，再生成一楼，底部「推演回执」或左侧「推演」可查看本轮结果及展开日志。
