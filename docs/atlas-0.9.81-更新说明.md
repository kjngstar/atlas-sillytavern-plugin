# Atlas 0.9.81

包含 0.9.80 的嵌套生成门控修复，并处理真实酒馆测试中发现的正文更新与回执缺失。

## 修复

- 提交前重新读取实际用户楼层和助手楼层。资料读取期间若宿主补写正文，重读资料后使用当前正文提交，最多重读三次。
- 用户正文被宿主改写时重新准备回合，更新 SQL 输入哈希与准备令牌，避免新正文被旧令牌拒绝。
- 模型请求期间仍检查完整正文与楼层身份；正文变动时不保存过期推演。
- 楼层失效、持续变化、过期提交都生成失败回执，可在「查看本轮日志」中定位原因，退出忙碌状态。
- 补充提交前的文本不匹配原因诊断，只记录原因枚举，不记录聊天正文。
- 宿主异步保存 SQL 候选期间，工作台读取同一候选快照时保留正在提交的会话，保存确认后才发布正式状态。其他外部快照替换仍会触发过期保护。
- SQL 调用遵守用户保存的 API 输出上限与超时，不再隐式压到阶段默认的 4096／2048 tokens，避免推理模型被截断却无法通过设置调整。

## 验证

- 类型检查通过；完整测试共 1628 项。
- 隔离 Chrome 使用实际安装包、SQL 引擎和原版 UI 检查 30 项生成路径，覆盖资料读取期间补写双方正文、请求期间正文变更，以及宿主保存期间的工作台读取。
- 上一版可复现资料读取期间补写正文后提交被拒绝；本版重读后提交当前楼层。
- 原版 UI 浏览器验收 59 项通过；最终安装包的 SQL 发布校验通过。
- 在真实 `http://localhost:8000` 酒馆中启用 shujuku 数据库插件，以独立验收聊天使用普通发送按钮生成正文，再由 Atlas 调用现有在线模型。01:49:07 的回执记录 `status: committed`、`coreSaved: true`，诊断记录 `COMMIT_SUCCEEDED`。
- 该在线回合为部分成功：1 组写入，6 组因模型引用不存在的 L1／C1 等编号被拒绝。该结果验证普通发送、推演、校验、回执与保存链路；不代表模型输出的所有操作都有效，也不把隔离响应计为在线模型实测。
