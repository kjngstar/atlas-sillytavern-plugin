# Atlas 0.9.82

修复首轮地点创建失败后，自动纠错仍无法建立地图的问题。

## 修复

- 明确语义操作的实际字段必须放在 `data` 内，新对象用 `new:`，已有编号只能来自本次目录；示例按阶段筛选。
- 未知短编号的命名新建操作可在定向纠错中修正为对应 `new:` 声明。只允许同一个原对象、相同操作类型和名称；原操作中指向该对象的依赖可同步修正。
- 拒绝借纠错改名、增加无关对象、声明其他票据的对象、重复未知编号，以及把已知对象更新改成新建。成功操作与原操作身份保持不变。
- 回执部分成功时明确显示「部分成功」，保留失败组与查看日志入口。
- 刷新后从 SQL 当前最新回合恢复补交入口，复核当前聊天、最后助手楼层与正文变体；缺失或已变动的楼层不恢复挂单。补交仍校验最新推演头，不重复成功事件。
- SQL 子地图按实际所属地点映射到城市、建筑、房间层级，修复 `site` / `interior` 被误显示为 L0 世界。
- 连续补交保存修正后的操作，更新当前失败诊断；地图维护记录按补交尝试区分，避免第二次补交与第一次地图写入发生冲突。
- 正式人物新建的提示词明确要求有依据的身份或重要性字段。
- 补交目录列出同批已经保存对象的稳定 ID，不重新分配原短编号；移除与当前允许操作不符的固定纠错示例。
- 人物的实际子地图点位优先于目录粗地图，修复车厢画布有人而侧栏计数为零的问题。

## 验证

- 类型检查通过；完整测试 1636 项全部通过；最终提示词与子图侧栏测试 42 项全部通过；SQL 安装包校验通过。
- 真实 SQL 测试覆盖失败地点声明的纠正、城市与建筑层级、人物位置、实际地图生成和聊天快照保存。
- 在线酒馆使用已存在的失败回合补交：实际保存 7 个地点、2 个人物、2 件物品及对应地图，原成功事件保留。最终关系补交与刷新验收结果在完成后记录。

## 使用

更新 Atlas 后刷新酒馆。对当前最新回合的失败组可使用「重试失败项」补交，已成功保存的事件不重复写入。
