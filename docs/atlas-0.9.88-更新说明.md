# Atlas v0.9.88

发布日期：2026-10-12。

本版将空间规划纳入生成流程：尺寸、陈设、走廊、父子图与真实物品关系在保存前一起完成。产品界面保留普通“生成布局 / 更新布局”，撤下独立历史修复窗口与绘图档案选择入口。

## 更新

- 根据已登记建筑和室外成员自动选择布局模板。明确来源支持的唯一走廊绑定到已有地点，不创建第五间普通房间。
- 陈设按完整尺寸摆放，尝试旋转与绕行，检查碰撞、门口和可达性。估计空间不足时进行有限扩展；确认尺寸、比例尺和锁继续保留。
- 父图足迹、房间与走廊子图、尺寸、共享陈设账本及真实物品支撑关系在同一原子空间组保存。陈设身份按空间 ID 复用，显式删除后不从旧账本复活。
- 同轮关联编译已经完成的排队请求不重复生成；关联地图的结构指纹一起更新。布局策略升级为 `layout-v4`，旧算法指纹在下次正常生成时刷新。
- 修正物理尺寸与格数换算、旧小数幅面及冲突尺寸别名；独立场地使用整个 `selfArea`，不把自己再画成内部小区域。
- 明确请求的已登记场地在模型格式失败时，可以依据已登记结构保存基础场地形状；未获得的模型细节仍显示部分完成。严格 JSON 校验与有限纠错保留，不截取坏 JSON 凑成功。
- 唯一可推导的路线地图归属在正常结构生成中填写；不同父地点的同名空间及无法唯一判断的历史冲突保持独立。
- SQL schema 升级为 3，增加来源、建设进度、布局指纹与空间陈设记录。旧档升级在副本中执行，并校验完整性、外键及原业务实体保留。
- 来源按实际发送块记录，建设目标暂停与重新启用可恢复调度；协议、策略和任务上下文分层，必需目录引用纳入冻结目录。
- 回执从持久回合及 journal 恢复本轮场景证据；失败更新不会借用旧场景宣称成功。修正问题计数、回退时钟、主角目录与已知容器导航，API 日志保留实际停止原因。
- 地图分析导出包含真实插件版本、布局策略、单位与幅面；适应视野按保存的几何范围计算。

## 验证与范围

- 干净依赖安装、类型检查、构建与打包通过；本版完整回归 **2102/2102 通过，0 失败、0 跳过**，耗时 77.843 秒，最终发布产物检查 **17/17 通过**。版本同步覆盖 package、manifest、扩展入口、服务端及 health 共 13 处。
- 本机酒馆实测：白桦附楼一次普通更新完成现存 11 件陈设，估计空间自动调整为 10×13 米，四间房和走廊与父图同步；庭院一次普通更新保存完整场地形状，幅面为整数 105×112 格。
- 旧档原始 12 件陈设在真实 SQL 的内存候选中自动调整空间并全部放下；这一副本验证没有写回当前聊天。
- 实机测试中无法唯一判断的六组历史重复地点候选和一条路线归属仍保留原值。确认或锁定空间确实装不下、模型细节失败、关联编译失败时仍如实记录问题并保护原组件。
- 空间仍是依据资料生成的估计示意，模型或连接失败不保证自动恢复；本版没有加入额外的两阶段 API。上述实机结果不代表所有历史验收项已经清零。
