# Atlas 0.9.93-rc.1 API 合批测试版

日期：2026-10-18。包含 [0.9.92-rc.1 地图修复](atlas-0.9.92-rc.1-更新说明.md)。组件版本为 `0.9.93`，测试版标识为 `0.9.93-rc.1`，数据库 schemaVersion 保持 3。

## 使用方式

更新扩展并 Ctrl+F5 刷新，在工作台设置的「任务与分批」中调整「API 分批设置」并保存。

| 设置 | 默认 | 含义 |
| --- | --- | --- |
| 每批人物上限 | 0 | 自动按连接输出容量合并，最多 24 人；可设 1–24 限制每批人数 |
| 每批地图上限 | 0 | 同类型、同依赖层的地图按容量合并，最多 8 张；可设 1–8 限制每批张数 |

0 是自动合批。正整数是上限；输出估算、输入长度和引用目录容量不足时仍会拆批。连接的输出上限为 0 时沿用 4096 token 的规划估值，实际 API 参数保持连接原值。人物仍按各自认知切片判断，不共享别人的私密信息。

设置随酒馆扩展设置保存，并包含在整套预设备份中；旧预设备份没有分批字段时保留当前设置。API Key 继续不进入导出文件。回执显示实际人物、地图批次数和每批对象数量，详细日志保留响应停止原因与耗时。

## 请求调度变化

- 人物批量由当前连接的输出容量决定，替换固定 4096 token 的人数估算；重要性、角色和所在地点相近的人物排在一起。继续结算也读取同一分批设置，只处理待办人物。
- 同类型且同依赖层的地图可以一次提交多张布局，程序逐图计算实际坐标。父图先落成，子图请求随后读取新轮廓；已由共享空间账本完成的子图直接复用，省掉重复请求。
- 一个操作共用一次位置资料提取，各地图只获得与自己有关的片段。一张图的依据失败时，其他通过校验的图仍可完成；失败父图的后代延期，避免无依据地单独画子图。
- 合批回复漏图时只补交未完成图；有效地图不整批重画。多图回复被截断时整段不落库，在剩余额度内缩小批量补交一次。
- 同一人物在相同世界时刻、位置和决策依据没有语义变化时，不因节点判断与收尾结算重合再次请求；认知、行动或接触机会改变时仍可重新判断。
- 观察、建设、后台、摘录、排版和重试仍共用每次操作最多 4 次真实传输预算。未完成部分明确保留待办。

## 本地验证示例

使用合成 SQL 世界和可计数的模型替身验证实际请求：

| 场景 | 请求结果 |
| --- | --- |
| 8 张同类简单地图 | 1 次共用摘录 + 1 次布局 |
| 12 张同类简单地图 | 1 次共用摘录 + 2 次布局，批量为 8 / 4 |
| 20 人，连接输出容量为 8192 token | 1 次观察 + 1 次 20 人决策 |
| 4 张地图，首次漏交 1 张 | 布局批量为 4 / 1，已完成 3 张不再生成 |
| 4 张地图，首次回复截断 | 布局批量为 4 / 2 / 2，截断回复不写入 |
| 父图已经完成共享房间投影 | 子图本地继承，不再单独调用模型 |

这些数字是可重复夹具的结果，不代表所有模型、地图复杂度或自定义提示词都有同样耗时。自动测试 2240/2240 通过（新增合批回归 18 项）；最终旧备份导入相关回归 66/66 通过。类型检查、打包和 SQL/WASM 发布检查通过。生产界面 87 项、宿主事件 30 项、联系传播 12 项、只读地图回放 9 项均通过，无浏览器错误。结果同时记录在组件 `ATLAS-PATCH-INFO.json`。浏览器使用实际发布代码与 SQL/WASM，酒馆宿主和模型由本地夹具提供；未在用户本机酒馆调用外部模型实测。
