# Atlas 0.9.94-rc.1 默认不限批量测试版

日期：2026-10-18。包含 0.9.92 的地图修复和 0.9.93 的合批功能。组件版本为 `0.9.94`，数据库 schemaVersion 保持 3。

## 分批设置

工作台设置 →「任务与分批」→「API 分批设置」。三个选项默认全部为 **0，不限制**，填写非负整数后保存。

| 选项 | 0 的行为 | 正整数的行为 |
| --- | --- | --- |
| 每批人物上限 | 不增加人物数量限制，取消原 24 人上限 | 按用户填写的每批人数拆分 |
| 每批地图上限 | 不增加地图数量限制，取消原 8 张上限 | 按用户填写的每批张数拆分 |
| 每次操作请求上限 | 不设置请求次数上限，取消固定四次 | 观察、建设、后台、资料提取、排版和重试共享该次数 |

API 连接的输出上限也设为 0 时，不发送 `max_tokens` 参数，由服务端决定可用输出容量；插件不再用固定 4096 token 估值拆批。连接中填写了正数时，按该输出上限估算批量，实际发送继续使用连接原值。

“不限制”指用户数量与请求次数不设额外配额。数据协议的响应字节、操作条数和引用目录容量仍须遵守。地图仍按相同类型、相同依赖层合批，父图先完成，子图再继承或细化。真实上下文超限、输出截断或协议装不下时才缩批补交；截断的人物回复整段不写入。

## 失败和兼容行为

- 不限制请求次数不会无限重试失败对象。每个未完成对象最多进入一次缩批补交；持续失败则保留待办和诊断，不重新生成已成功对象。
- 正数请求上限按真实传输计数，包含兼容路由重发。达到上限后未完成任务保留待办，可以继续处理。
- 旧设置没有请求次数字段时，首次读取缺省为 0。旧备份或旧设置命令没有该字段时，不清除当前已经保存的请求次数设置。
- 之前手动保存的人数、地图正数上限会保留；改成 0 并保存即可解除。默认 0 的旧用户直接获得新的不限行为。
- 大批量人物显式补入本批必要引用，避免全表目录的旧扫描前缀遗漏后面的角色。

## 验证范围

使用真实 SQL 和可计数的本地模型替身验证：50 人不受原 24 人上限影响；250 人可同批处理并修改目录扫描前缀以外的人物；600 人按引用协议容量分为 512 / 88；20 张简单地图可一次规划；设置小批量后可以完成超过四次请求的任务；正数限制仍生效；截断、上下文超限和持续失败都不会无限重试。

自动测试 2252/2252 通过，类型检查、打包和 SQL/WASM 发布检查通过。生产界面 89 项、宿主事件 30 项、联系传播 12 项、只读地图回放 9 项均通过，无浏览器错误。验证结果同时记录在组件的 `ATLAS-PATCH-INFO.json`。宿主和模型使用本地夹具，未在用户本机酒馆或外部模型实测。
