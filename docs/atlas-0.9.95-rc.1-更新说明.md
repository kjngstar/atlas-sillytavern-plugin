# Atlas 0.9.95-rc.1 按工作分批测试版

日期：2026-10-19。组件版本 `0.9.95`，数据库 schemaVersion 保持 3。包含前几个测试版的地图、载具入口与合批修复。

## 设置与请求控制

工作台 → 预设 → 任务与分批 →「按同类工作分批」。地图布局规划、人物判断、空间资料提取和事件结果判断默认各 1 批；填写 3 表示将对应工作分成最多 3 个非空批次，每批尽量一次请求。

正常请求和失败补交分开计数。整轮额外请求额度默认 1，可设为 0；传输重试、连接兼容路由重发、格式纠错和漏项补交共用该额度，不逐层领取新额度。旧总请求保险上限仍可进一步限制实际发送次数，0 表示按工作计划控制。

旧人物、地图「每批对象数」独立保留，不把 24 人误解释为分 24 批。保存新工作分批设置时会清除旧对象数量上限并改用批数；旧总发送保险上限保留。旧备份没有工作分批字段时保留当前工作设置，API Key 不进入导出文件。

## 地图处理

- 保留先提取空间证据、再生成布局约束的两步流程。第一步按用户批数覆盖完整输入范围，同一次操作内的地图共享结果，不因每张图或层级重复提取。
- 同一规划请求可以同时包含 overview / city / floor 及多层父子图，一次返回各图的约束。父子关系和共享物理尺寸进入同一目录与上下文。
- 程序按父图到子图的顺序求解坐标、继承轮廓；本地摆放和绘制不增加 API 请求。规划前已知的子图尺寸同时供父图投影使用。父图失败时保留子图约束并延期，不发布脱离父图的细节。
- 新工作流程的结构建设不再因单批 12 个新增地点或向下 2 层而截成多个小任务；仍遵守已冻结目标范围、输出操作和引用等协议容量。来源或协议预算的待办继续明确保留。
- 容量估算装不下设定批数时，发送前提示增加批数；实际上下文超限或回复截断也不连续自动缩批。已完成地图不重新生成。

仅地图排版在容量足够、无失败且有来源材料时，目标为 1 次共享提取 + 1 次统一布局规划；没有来源材料时省略提取请求。首次世界建设还可能包含观察登记、结构建设等阶段，普通回合也可能触发人物或事件工作，并非所有操作固定两次。

## 人物、事件与继续处理

- 人物按剩余目标和剩余计划批次均衡分配，保留各人物的认知范围与写入权限。
- 同一因果时刻、同类且不同执行者的节点或到期行动可合批；有明确依赖的工作、不同时间的因果边界继续顺序推进。
- 结果只覆盖部分到期行动时，已落实结果保留，其余行动停在当前因果时刻等待处理，不把整个批次伪装成完成。
- 已用批次和实际发送数保存在回合中。继续处理不会重复观察或重置配额；用户增加对应工作批数后才获得新增正常额度。
- 回执显示实际发送数、额外额度用量以及人物和地图的每批数量。无发送的容量检查不算 API 调用。

## 调度参考与验证

参考 [AlbusKen/shujuku](https://github.com/AlbusKen/shujuku/tree/4b311a61ae7e37154c624a2ed1b771000ac5d11a) 的同组多表请求、共享读取范围和统一提交方式；批次在 Atlas 中对应同质规划工作。保留现有 SQL 编译校验、隔离候选、宿主保存确认和回退流程。

本地 SQL 夹具已验证：12 张图为 1 次提取 + 1 次规划；12 张图分 3 批为 4 / 4 / 4；四层、三种地图类型共用一次规划；20 人分 3 批为 7 / 7 / 6；同一时刻两项独立行动共用一次结果请求；继续处理保留已用额度；连接兼容重发也计入额外额度。

最终回归和发布检查结果记录在组件 `ATLAS-PATCH-INFO.json`。宿主与模型使用本地夹具，未在用户本机酒馆或外部模型实测。

最终验收：2270/2270 自动测试通过；类型检查、打包和 SQL/WASM 发布检查通过；生产界面 97 项、宿主事件 30 项、联系传播 12 项、只读地图回放 9 项均通过，无浏览器错误。发布包自动回合夹具为 4 次正常请求，其中四层、三类地图共用 1 次规划，额外请求为 0；宿主只保存一次，删除楼层可以回退。
