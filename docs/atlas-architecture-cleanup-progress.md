## Q05：正式 SQL 时间、后台因果结算与原楼补算

正式 Repository 在隔离候选内调用既有时间、移动、行动、接触、人物决策、到期结果和传播模块，所有变化写入同一楼层 journal，保存确认前不发布。短对话和未完成计划贡献零耗时；完成的休息等行为依据明确区间或默认估计推进，完成的赶路可按真实路线及已有移动能力计算；无依据的完成行为记录 TIME_UNRESOLVED，不假称成功的零时间。

到期结果实际编译并应用语义操作，不再只记录响应摘要。模型失败或预算耗尽停在最早未决边界，分支标记 catching_up；保存的原楼可继续后台结算，不重复正文、不再推进时间、不改变业务 head/revision。50 人分批判断仅继续待处理人物。原操作与每个后台批次的短引用映射单独保存，自动纠错和手动补交沿用原目录，新增地点不会造成引用错位；人物决策补交仍受原人物权限限制。

传播按出发和到达时刻保存中途任务（复用 actions），抵达只建立当地消息前沿。真正的个人认知由接触机会和 attention 决定；私密渠道只允许指定接收者，不给其它在场者自动赋予知识。后台人物输入只包括其已有认知和有效接触，不发送作者独有的消息正文。重大结果使用可复现随机种子并保存抽签记录。历史已到达行程不在新回合反复覆盖人物的新位置。

回退恢复原楼及其后文，并把 head 恢复到仍有效的父楼；迁移基础楼保留。分支的 POV、根图、时间区间、结算游标和状态也恢复。行动与结果事件形成相互引用时，在候选回退事务中延迟外键检查，事务结束仍通过完整一致性与外键检查，没有关闭外键。
