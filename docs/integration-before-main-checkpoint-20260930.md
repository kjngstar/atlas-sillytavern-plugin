本地 SillyTavern 8000 的最终实测使用原有的 `atlas-sillytavern-plugin` Git 安装目录。先前误开的 8001 测试进程已停止，其两份临时插件目录已移除。专用测试角色「Atlas 自动化验收 20260930」的一次完整回合记录了：自动开场成功 1 次，3 个地点、2 个人物，普通回合提交和世界书同步成功。概览及附近在下一次只读打开时分别显示「图书室」和在场人物。地图只读复核可从「星河中学」示意点进入「教学楼」，再进入「图书室」；标尺仍明确显示「未标定」。脱敏诊断见同目录 JSON。模型另有 2 行因 `INFERRED_FIELD_NOT_ALLOWED` 被拒，合法行仍被采纳；这是有记录的部分接受，不是丢失整轮。酒馆主模型该回合响应较长且耗时明显，故没有继续消耗 API 跑第二题材和更多交互场景。

世界书真实宿主补验：两本各 120 条的专用验收书仅绑定测试角色；B 书末尾 UID 119 编辑后，普通回合的实际模型请求带新标记。宿主实际发出 16 个激活身份；最终回合在 245 个候选中选 8 条、输出 2,120 字，诊断为 `host-activated`，Atlas 提交第 36 楼成功。此前逐字比较宿主扫描时和提交时的用户文本会误判激活事件，现改用聊天、角色、楼层索引及宿主楼层对象身份；编辑/删楼事件清除旧记录。另一次普通回合曾出现模型请求已发出但浏览器关闭前未见提交，后续三次普通回合成功，仍需关注间歇性延迟。

第二题材真实宿主补验：仍用专用验收角色，但新建独立聊天并将首条开场设置为荒野驿站场景。第一次用户消息前只观察到一次 `SCENE_BOOTSTRAP_COMPLETE`；最终当前地点链为「荒原 → 风蚀驿站」，未具名的灰斗篷旅人建档，随后普通回合提交成功，世界时间为 0。该测试没有改默认提示词，也没有在真实用户角色下运行。

A/B 聊天按学校→荒野→学校→荒野顺序切换；每次 `/state` 与聊天 ID 匹配，学校只出现图书室/夏语冰，荒野只出现风蚀驿站/灰斗篷旅人，当时各自已提交楼层分别为 36 与 2。390×844 真酒馆窄屏初次测试发现窗口被酒馆主题高度为 0 的 `html` 定位到屏幕上方；改用 `50vh/50vw` 后窗口完整落在视口内。随后用测试浏览器临时隐藏其他扩展的新手引导，未改该扩展设置；真实 Atlas 安装下逐层点击「星河中学→教学楼→图书室」示意点及子图入口，Escape 关闭弹卡，放大控件由 100% 到 125%，比例尺由约 37.2 格到约 29.8 格且始终标为未标定。初测中面包屑遮挡缩放、空白区域遮挡人物点，经修复后重测通过。一次酒馆原生 swipe 调用只产生空的新候选，原候选和 Atlas 回执保持不变；成功 swipe 的回退与重提交仍未得到结果。随后在专用荒野聊天删除已提交的第 2 楼，酒馆楼层从 3 变 2、Atlas `lastCommittedMessageId` 清空，诊断为 `WORLD_TURN_TABLE_ROLLBACK`；开场位置链仍保留。另用浏览器请求拦截暂缓学校聊天的 Atlas 模型调用，切到荒野聊天后放行；荒野的状态 ID、驿站位置和旅人人物均未被迟到请求污染。该浏览器最终关闭前原请求未给出成功回执，学校聊天仍保留先前的提交楼层 36，因此这项只证明不串聊天，尚不能宣称迟到请求在原聊天成功落盘。

同地/远方可见性首次真实聊天补验：专用新会话开场和主模型正文生成成功，Atlas 世界回合模型也返回 8,906 字；唯一的 `currentAction` 行却把远方动作标为 `inferred`，服务端按契约拒绝，`WORLD_TURN_DELTA_REJECTED / PARSE_REJECTED`，整轮没有提交。默认与作者视图都无新摘要，因此不能将这次计作可见性验收通过，也不能凭正文中出现远方动作宣称主角已知。

同会话补充回合成功提交，当前地点链为「石塔→钟座」；默认视图显示主角与伊莱恩在钟座的可见行动，作者视图另有远方大厅的深色晶体隐藏记录。塔尔的远方 `currentAction` 行再次因 `inferred` 被拒，不能宣称远方 NPC 行动门槛通过。根因是默认提示词没有说明 `observed` 指助手正文有逐字事实证据、并不表示主角知情；已补充这一条和 `currentAction` 的依据限制，等待更新真实酒馆后复测。此提示词改动经过类型检查、完整 1,336 项测试、构建及打包，退出码均为 0。

更新 8000 端口原有 Atlas 安装后，以同一测试聊天最新助手正文执行「立即推演」：回执为 `committed`，默认视图只含同地伊莱恩「在窗前守望」，作者视图额外含 `hidden` 的塔尔「返回住处休息」。这证明远方 NPC 行动在实际宿主的两种视图中隔离；该回合复用了已有正文，仍需普通新回合与消息送达测试。另一条 `simulation.propose` 被拒为 `SIGNAL_KIND_INVALID`，因为内置提示词只提允许此表却未说明 `kind` 只能为 `signal`；已补充格式示例和无真实发信就省略的限制，待复验。

失败/重试首次宿主补验：测试浏览器仅将一次 Atlas 模型请求模拟为 HTTP 502，插件显示错误并保留原 `userMessageId`、`assistantMessageId` 的可重试挂单，失败请求没有新增提交回执。用原挂单触发 `/turns/retry` 后，实际模型请求在 120 秒超时，挂单仍保留、世界仍无这次回执。由此只通过失败状态保护，成功重试门槛仍未通过；模拟 502 不代表真实网关故障。

随后在独立的短正文测试聊天复核：先创建并绑定世界，再对一次「立即推演」的 Atlas 模型请求模拟 502，失败时回执数为 0 且挂单可重试；用原挂单重试，真实模型返回 200，最终只有一条 `committed` 回执，错误与可重试挂单均清空。这通过了原酒馆中的失败→重试成功链；长正文请求仍曾超时，不作性能稳定性结论。

右滑补验修复了真实兼容性问题：酒馆在新候选生成前先把 `swipe_id` 设为旧 `swipes.length`，Atlas 原判定只认数组内最后一项，漏掉新生成。先前直接调用底层 `Generate('swipe')` 的空候选测试也不走完整右滑流程。改用酒馆 `swipe_right()`、且最近 Atlas 回执确实属于待右滑的助手楼层后，在事件当刻观察到 `swipe_id=2`、`swipes.length=2`；修复版判为新生成，记录 `WORLD_TURN_TABLE_ROLLBACK`，新候选生成后 `COMMIT_SUCCEEDED`，最终 `swipes.length=3`、当前 ID 仍为同级楼层 6。已有非空变体只浏览不回退、数组外待填槽和数组内空占位均有针对性测试。

尚未完成的扩展场景：消息真正送达主角后的可见性、迟到请求在原聊天的最终回执、载具在途。远方人物的作者/默认视图隔离已在实际宿主的立即推演中通过，普通回合可见性还需更稳定的模型输出。对应自动测试存在，但不能冒充真实酒馆结果。原施工单要求全部 M3 人工场景通过才合并；作者随后明确把本次发布条件调整为「基础功能没什么问题」，因此本次按已通过的开场、世界书、地图、聊天隔离、失败重试与原生右滑基础链评估，余项作为已知验收限制公开记录。
