# 地图层级、主空间与真实几何修复

本轮针对最新地图分析导出中出现的楼层平铺、直属空间漏绘、厨房仅剩储物间，以及真实建筑被装饰淹没的问题。分析文件只有已过滤视图和布局，没有原始世界书，不能据此给房间补造楼层归属。

## 最终行为

- 建筑内已有楼层使用楼层选择器；建筑总览按楼层、房间、建筑、载具、室外场所分组。与楼层并列的房间显示“楼层未标明”，保留原归属和真实入口。
- 当前地图没有表达的直属空间显示“位置待完善”；子图没有布局则显示“内部待布局”。导航、展开列表和切楼层不调用模型。
- 树与路径显示真实空间类别；路径阶梯只列实际祖先，不补出不存在的中间层级。
- 楼层不参与普通房间排位、占地膨胀或概览中的室外区域生成。旧场景中的楼层平面投影在显示时移除，原存档和独立楼层图保留。
- 含子房间的房间保留自身的主空间。主空间人物、陈设和物品使用容器自身的 ID；子房间作为障碍参与主空间的放置与可达性计算。入口发生冲突则拒绝替换布局。
- 主空间陈设沿用已有空间账本，不因存在储物间而误交给后代空间。地面物品保存 `roomId`，避免刷新与视角过滤时丢失。
- 已保存场景缺少人物或物品锚点时，显示层补用当前 SQL 点位，格到米只转换一次；已有场景锚点优先。缺尺度不塞入错误坐标，POV 隐藏对象不补绘。
- 城市与建筑不继承宏观地图的同级区域取景；街区仍保留原来的父级边界和相邻街区导航。
- 正式城市不再每街区随机绘制 190 个装饰块，改画保存的真实建筑轮廓和示意道路。新城市默认 `blocksPerDistrict=0`；显式设置和旧场景的装饰约束仍能读取。
- 建筑分区遵循登记的父级，不能因示意排位被塞进任意首个街区。锁定布局与归属矛盾时报告冲突。
- 未标定概览的格幅面不能当成同等数值的米制尺寸写入空间权威。估计房间容量按两侧实际宽度之和计算，保护已确认尺寸。
- 分析导出追加原有完整性评估和导航覆盖情况，区分有效场景、绘制缺项、未生成内部布局。

插件版本保持 `0.9.96`；布局策略更新为 `layout-v15`。

## 验证

- TypeScript 检查、安装包构建、完整 Node 回归。
- 匿名结构回归：厨房与储物间同时存在、主空间人物与地面物品、陈设账本身份、入口冲突、POV 过滤、跨单位点位补绘、楼层导航、城市分区与实际绘制命令。
- 真实 SQL 流程覆盖任务组装、占用者对账、自动布局、空间账本、地面物品补点；不改人物的 SQL 归属。
- 最新导出的 48 张地图只读回放，验证节点保留、所有子图入口、楼层选择、主空间人物、城市取景和窄屏；用户的完整导出与截图不提交仓库。
- 正式浏览器门禁覆盖现有地图交互、工具收纳和皮肤渲染。

## 使用边界

显示修复能在读取旧场景时生效；生成器与空间账本修复需要更新受影响图的布局。仅打开地图不自动请求模型，也不会把分析 JSON 当存档导入。

本次导出中只有 6 张地图有场景，另 42 张没有场景。修复不会把它们冒充为已生成地图，也不会给缺乏来源的房间自动编造“一楼”归属。原始空间事实仍由世界书、故事及作者登记决定。

浏览器验证使用本地隔离宿主和 SQL/WASM；没有操作用户正在运行的 SillyTavern，也没有调用外部模型补造地图。
