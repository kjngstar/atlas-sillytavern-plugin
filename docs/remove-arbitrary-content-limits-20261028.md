# 移除无实际依据的内容上限

基于 `0.9.99`，针对预设、SQL 操作与空间内容的固定边界进行修复。

## 行为变化

- API 与提示词预设不再受后端 20 套、编辑器 50 套的数量限制。保存、重载和导入使用同一规则。
- 提示词不再受 8,000 字符、16/64 个分段等限制；原生包、外部预设和兼容草稿完整保留有效条目。编辑器也不再用另一套 `maxlength` 截断内容。
- 保留完整的名称、模型、端点、密钥、连接覆盖提示词、附加请求体、排除字段和标头，不再截取前 2,000/4,000 字符。类型、有效 URL、重复 ID 和活动绑定检查继续执行。
- 通用操作解析器不再拒绝超过 8 KiB 的单条操作，也不再丢弃第 65 条以后的有效操作。布局仍在进入生成器时按其真实输入字节预算检查，解决“内层允许 64 KiB，外层先按 8 KiB 拒绝”的冲突。
- `space.state.patch` 的规范化和编译层均移除每条 32 个对象的限制；对象身份、字段类型、作者锁和跨图检查保留。
- 地图不再按房间、陈设、人物、物品、街区、建筑、概览分区、地物和连接的固定数量拒绝或截断。人物目录与陈设账本的读写、合并及提示词输入也同步移除旧裁剪。
- 不再用 40/100/20,000 米等固定边长判断空间“不可能存在”。有限正尺寸、真实容纳关系、导航预算和碰撞/通路约束继续决定布局能否生成。
- 别名、能力、移动方式、物品属性和事件参与者不再受 8/16 项的固定上限影响；写入与数据库不变量采用相同规则。

## 任务预算与内容校验分开

`constructionBudget` 仅执行调用方明确提供的工作额度。未提供共同总额时返回 `totalOperations: null`，避免用 `Infinity` 写入 JSON 后产生含糊的值。显式有限总额和地点/路线分类配额仍会把未完成工作交回队列。

原 `operationsPerResponse` 已移除。保留的 `constructionOperationsPerBatch` 只是建设任务的默认规划量，不是解析器接收回复的硬上限。调用方明确提供的分类工作量也不再被默认值强制压低。

用户保存的请求次数、工作分批、输出上限、API 绑定和暂停/保存确认流程不变。移除内容限制不会新增自动请求通道。

## 继续保留的约束

- JSON 语法与嵌套深度、字段类型、引用存在性、来源及聊天/分支/修订身份。
- 作者确认与锁定事实、几何容纳和碰撞/通路判定、事务与保存 ACK。
- 当前引擎的总体回复字节、生成器输入/场景字节、导航网格、渲染路径和分页账本的资源预算。达到这些预算时必须给出诊断并保留旧记录，不能把合法内容偷偷裁短后冒充成功。
- 历史兼容数据模型和既有调度协议中的其他约束不因本次内容容量修复被一并删除。

陈设数量放开后，若完整的新场景与账本超过整体框架预算，整个变更返回失败；不能写入新场景却悄悄沿用旧账本。

## 验证

- `atlas-content-capacity.test.mjs` 覆盖原 8 KiB 布局冲突、100 条操作、完整建设配额、25 套预设、长配置和提示词、70 段编辑器往返、30 个房间及 150 条旧陈设。
- 状态补丁测试经真实 SQL 提交 40 个不同对象的变化并逐项读回；地图几何保持原样。大型别名和能力列表同样经过真实 SQL 提交与重读。
- 原限制测试改为验证完整保留；同时继续测试非法输入、过期作用域、有限工作额度及总体资源预算。
- 执行类型检查、镜像同步、构建、自包含打包和完整 Node 回归。准确的最终结果记录在本分支 PR。

最终验证：3027/3027 项 Node 回归通过，0 失败、0 跳过；类型检查、镜像同步、构建、自包含打包、引用审计与 `git diff --check` 均退出 0。发布包内的真实解析器接受 8,509 字节布局及完整 100 条操作。源码提交 `17dcd70490122bc977e1fbb225e18c688cb8bd3f`，构建标识 `build-de771b00e1fcb346`，`buildDirty=false`。
