# 两阶段地图规划 · 2026-10-29

## 变更

日常地图更新由四种独立模型任务改为两阶段：

1. 观察实际变化并读取空间事实。程序保留带来源 key、内容 hash、原文位置的来源，不再付费调用独立摘录模型。
2. 在同一个 JSONL 响应里规划地理结构与布局。程序先按原有规则校验并登记地点、路线和尺寸，再解析布局草案、求解几何和保存。

已有地图用稳定地图 ID；同批新增容器用 `data.container_ref` 指向已登记地点或本批 `new:` 声明。布局仅解析登记成功的实体；只转换布局协议的引用字段，不改写家具局部 ID 或显示文本。沿用原有作者锁、父子尺寸、候选事务、变更日志和保存校验。

只有布局需要更新时，直接携带原始依据发出一次布局请求。多个用户配置批次仍按批发送；遗漏项修复、网络重试、到期人物行动另计。两阶段不等于任何操作都保证两次网络发送。

当前主客户端使用合批流程；不带 workload 配置的旧端口保留阶段式兼容行为。用户已保存提示词和连接配置保持原样。
