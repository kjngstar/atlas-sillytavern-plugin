# 主 API 空回复与世界书预算修复

## 核对结果

- 基线为 main / `aa387f9`（已发布 0.9.86）。此次为本地修复，发布版本号尚未变更。
- 用户提供的诊断文件记录了 09:41 与 09:46 两次酒馆主连接空回复。适配层自行生成 `ok:true / status:200` 的错误信封，日志因此误记为模型 HTTP 成功；该状态不能证明供应商确实返回 HTTP 200。
- 世界书普通回合有三处 6000 字限制：宿主选取、commit 契约、旧接口的提交后地理请求。它是输入限制，与输出 token 上限无关。
- 本机当前主连接在改动前已能返回有效内容，原来的两次空回复未稳定复现。不能仅凭历史日志确定具体提供商/网关原因，也不能把所有空回复归因于输入预算。

## 修复

1. 普通回合完整保留启用世界书条目及正文；不再默认限制总字符、单条正文或条目数量。显式调用纯选择函数的预算仍有效，省略预算代表不截断。契约和提交后地理请求均不再截断世界书。
2. 主连接请求酒馆助手返回详情，并兼容旧版字符串。识别详情对象的正文、推理字段和已经支持的响应工具信封；未知或多个工具调用拒绝，不执行任何工具，不增加补发请求。
3. 宿主错误使用带 `atlas-host` 来源的本地失败响应。客户端保留实际原因，不再附加“HTTP 200 / 模型不存在 / 地址错误”的通用猜测。
4. 主连接记录 `MODEL_HOST_COMPLETE / MODEL_HOST_FAILED`、正文长度及失败原因码。供应商 HTTP 状态不可观察时，模型尝试的 HTTP 状态记录为 null；本地状态不冒充供应商状态。
5. UI 将已保存的部分提交显示为 `TURN_PARTIAL` 警告；真正失败和具体问题仍按错误显示。

## 验证

- 类型检查通过。
- 针对性测试覆盖 76 条、超过 3 万字符的世界书，逐条验证完整正文经过选择、commit 校验和实际 API 消息装配后仍保留，包括最后一条地点资料。
- 覆盖酒馆助手字符串/详情对象/推理/工具信封、空回复/未知对象/非法工具、单次调用、真实错误分类及未知 HTTP 状态。
- 最终构建完整串行回归通过 1863 项，失败 0；类型检查、镜像同步与自包含打包通过。
- 本地酒馆独立验收聊天实测：10:34 的主连接 observe、construction、layout 三次返回正文长度 13、13、720；布局与回执实际保存，6 个组成功、0 个组失败，coreSaved=true。状态为部分提交，不能宣传为全部世界建设完成。
- 最终构建 10:42 再次实测：observe 返回 273 字、layout 返回 721 字，8 个组成功、0 个组失败、issues=[]、coreSaved=true；尝试记录 httpStatus=null，汇总日志为 warn / TURN_PARTIAL。截图见 [主连接返回与已保存回执](reference-ui/host-main-response-fixed-20261010.png)。
- 本次实测世界书 120 条全部保留、截断 0、5659 字。超过 6000 字的完整传输由上述回归测试验证；本次在线场景没有长世界书，不能把它当成长上下文在线压力测试。
- Kemini 脚本网关仍由酒馆运行，Atlas 没有内置该脚本。实测控制台可见传输信封解包；没有切换到另一连接来代替主连接验收。

## 使用范围

本次取消的是 Atlas 的世界书输入截断。服务商上下文窗口与酒馆连接参数仍决定请求能否被上游接受。原始空回复的供应商根因尚无足够证据；此次修复确保有效返回不会因对象形状被误读，并让失败日志准确反映实际观察。
