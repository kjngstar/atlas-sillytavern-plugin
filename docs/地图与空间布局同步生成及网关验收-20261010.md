## 修复

- map/bootstrap 自动启动布局，与观察、世界建设和地图登记共享候选事务。
- 布局按两张一批，在本轮剩余预算内连续处理；所有批次统一绘制并保存。预算未足的历史地图明确保留为待处理，后续普通推演自动继续。
- 空间绘制数量随本轮实际选中的地图数调整，避免模型已返回四张布局却只绘制两张。
- 正确识别省略 status 的 pending 布局请求，为每批成功布局保存结构指纹，避免下轮重复生成。
- 世界建设 ready 必须有真实场景。只有进度元数据发生变化时，不再记为世界业务变化；三次模型均失败且无有效变化时丢弃候选。
- 回执的成功组不包括纯建设进度组；诊断补上不属于业务分组的模型、建设和布局错误。
- 主 API 优先使用酒馆 ChatCompletionService 装配原始请求，通过发送时的全局 fetch 进入现有脚本网关，直接读取完整响应，避免已装配的来源目录再次执行 EJS。旧宿主仍保留助手兼容通道。
- 读取 Gemini 原生 functionCall 和酒馆 responseContent 信封，只解码允许的回复载体，不执行返回工具。
- 诊断保存通道、酒馆端 HTTP 状态、结束原因、工具数量和响应长度。酒馆端 HTTP 状态不冒充供应商 HTTP 状态；日志不保存正文、提示词或凭据。
- 默认估计城市幅面满足求解器的 900×700 米要求；已标定尺寸保持原值。

现有外部 Kemini 脚本未被内置。此前移除的 6000 字符世界书输入上限继续保持移除。
