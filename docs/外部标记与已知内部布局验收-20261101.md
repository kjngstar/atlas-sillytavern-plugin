## 规则和实现

只有外观、招牌、名称的叶子地点保留在父地图，不自动创建内部地图。实际 NPC/物品所在地点、已有下属空间、同一规划响应返回的有效内部布局仍可展开，并维护必要的祖先地图；已有地图不因人物离开而删除。单凭 `room` 类型或空布局请求不足以展开。

源码 `15b2a47` 增加展开规则，`25ffc0a` 修正同响应布局与陈设的承接：未显式填写 status 的待处理请求也按 pending 处理，避免父图先生成空子房间、吞掉子请求中的陈设。正常批次冻结的地图目标也纳入同一响应明确要求的新子图。
