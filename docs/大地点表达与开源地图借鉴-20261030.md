# 大地点表达与开源地图借鉴（2026-10-30）

大地点应展示可理解的空间组织：地形、通路、功能区域和可进入的子地点。只有一个地点名和计算画布时，不应把画布画成地点边界，也不应将空壳当成已经生成好的地图。把矩形换成随机多边形仍不能解决内容为空的问题。

## 当前代码中的原因与已改动

`vendor/atlas-spatial/overview-core.mjs` 在没有子地点轮廓时，用 frame 生成 `selfArea`；该字段明确标记 `source=frame`、`quality=layout`，但旧 UI 仍把它画成大虚线矩形，中央再标当前场所名。风铃渡口虽然有候船棚和埠头两个子地点，保存的场景里尚无它们的地理落点，因此只看得到自己。

本次显示修复分两步：

1. 投影层不再将 frame 来源的自身示意当边界绘制；真实 canonical / confirmed 边界继续保留。当前容器也不重复作为图内子地点标记或房间中央标签，实际墙体、陈设、子房间、道路和地形保留。
2. 没有可用地理结构或已定位子地点时，在视口展示已有子地点的结构概览，明确提示实际位置与距离尚待确认。可进入已有候船棚、埠头等子图；没有内部记录时显示中性的状态和返回上级入口。获得真实几何后自动恢复地图，浏览不触发模型建图。

结构概览表示归属，不将卡片位置、顺序或连接误当作米数与通行路线。该修复兼容旧聊天，不改地点 ID、数据库坐标、场景几何或存档比例尺。它解决误导性的空框显示，没有修复上一轮验收发现的陈设搬动未落地、重复主角、石桥缺桥面等生成问题。

## 重点参考项目

### 1. Azgaar Fantasy Map Generator：地区与世界组织

[仓库](https://github.com/Azgaar/Fantasy-Map-Generator) · [MIT 许可](https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/LICENSE)

最适合借鉴聚落、道路、河流和标签的分层组织，以及生成、编辑、渲染分工。核对当前代码：

- [routes-generator.ts](https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/src/model/economy/routes-generator.ts)：道路、路径与水路围绕聚落、地形和水域条件生成，而非仅把名字散布在大画布上。
- [burgs-generator.ts](https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/src/model/political/burgs-generator.ts)：聚落位置、港口条件和道路相关联。
- [labels-generator.ts](https://github.com/Azgaar/Fantasy-Map-Generator/blob/master/src/model/annotations/labels-generator.ts)：标签应服务实际地理对象。

对 Atlas 的对应：地区总览优先显示已知聚落/入口与真实交通网络；缩放改变显示细节，世界距离不随排版改变。不整包替换持久世界引擎。

### 2. Watabou TownGeneratorOS：城镇内部的功能结构

[旧版开源仓库](https://github.com/watabou/TownGeneratorOS) · [GPL-3.0 许可](https://github.com/watabou/TownGeneratorOS/blob/master/LICENSE)

这是旧版城市生成器源码，README 明确说明缺少当时线上版本的一些功能，依赖 Haxe/OpenFL；不能把当前在线产品的全部能力视为仓库已提供。核对：

- [Model.hx](https://github.com/watabou/TownGeneratorOS/blob/master/Source/com/watabou/towngenerator/building/Model.hx)：分块、交叉口、街道、功能街区和建筑几何分步骤生成。
- [Ward.hx](https://github.com/watabou/TownGeneratorOS/blob/master/Source/com/watabou/towngenerator/wards/Ward.hx)：按临街边界和道路等级留出空间，再生成街区中的建筑。

这是本次最贴近“这一层需要有东西”的结构参考。大城镇需要街区、出入口和道路，港口需要岸线、集散空间、等候设施与泊位；不以一个单空间矩形代表整个大地点。可以研究其算法组织并为现有 JS 数据契约独立实现；直接引入源码需要先按其许可确定集成方式。

### 3. Red Blob Games mapgen2：自然区域与地形依据

[仓库与实现说明](https://github.com/redblobgames/mapgen2) · [Apache-2.0 许可](https://github.com/redblobgames/mapgen2/blob/main/LICENSE)

JavaScript 的多边形地图生成实现，将网格拓扑与生成世界数据分开，可替换采样、噪声及随机序列，使用种子生成地形、河流和生态区。适合山林、河谷等大范围自然区域；不负责房间陈设或城市功能结构。

对 Atlas 的对应：自然边界与河网应由共同地形关系生成，避免任意孤立多边形；河流和道路之间应有一致的桥梁/过河节点。固定地点种子与已确认几何，后续只补差量。

### 补充：mewo2/terrain

[仓库](https://github.com/mewo2/terrain) · [MIT 许可](https://github.com/mewo2/terrain/blob/master/LICENSE.md)。适合阅读自然地形与制图表达的简洁实现。作者明确表示项目已完成，不提供持续维护支持，因此更适合作为算法参考。

## 适配顺序

先明确大地点的语义和可达结构，再生成几何。模型负责依据与功能需求，算法负责入口、连通、分区和几何约束，渲染只读取结果。地区/城镇显示道路和功能区域，建筑层显示空间组合，进入房间后才显示墙体、门窗与陈设。

未确定内部时先保留可浏览的实际子地点，随着探索或建设补齐功能分区和路径。通行线只能来自已确认或明确标为估计的关系，不能将纯排版连线写成真实道路。背景质感与可交互地点分别处理，补图不应重建既有实体或抹去玩家搬动的陈设。

本次未引入第三方代码或新增依赖，参考项目用于研究，不将其完整随机世界生成流程直接接管 Atlas 存档。
